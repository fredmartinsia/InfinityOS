## Jornada Profissional

### Fase 1 — Inicio na engenharia frontend (~2017-2019)

Emil comeca a carreira em frontend, com passagens em empresas europeias do ecossistema fintech/payments (referencias publicas mencionam SumUp e familiaridade com o ecossistema Stripe). Desde cedo o foco esta em UI: fontes, espacamento, hover states, micro-interactions. Animacao ainda e tema secundario nessa fase, mas o gosto pelo detalhe ja esta presente.

### Fase 2 — Vercel (Design Team) (~2021-2023)

Emil entra no time de design da Vercel, no momento em que a empresa esta consolidando reputacao como referencia de design web (vercel.com, dashboard, geist design system, painel de deploy com animacoes proprias). Foi durante essa fase que:

- **Sonner foi criado.** Emil queria um toast component "feito direito" — empilhavel, swipe to dismiss, com spring animation, com api ergonomica (toast.success, toast.promise). Lancou como open source. A comunidade adotou imediatamente.
- **Vaul foi criado.** Emil queria um drawer iOS-style "feito direito" — snap points, drag handle, scroll lock condicional, easing iOS, nested drawers. Lancou como open source. Virou padrao de mercado.
- **Reputacao no Twitter cresceu.** Threads densas com video + codigo, mostrando detalhes de animacao que outros nao notam. Comecou a virar referencia.

### Fase 3 — Linear (Web Team) (~2024-presente)

Emil migra para a Linear, no time que cuida da camada web (site marketing, web app de produto). Linear e provavelmente a empresa onde animacao de componente importa mais — todo o produto e construido em torno de feel, responsividade, animacoes que somem antes do usuario perceber. Faz sentido logico Emil estar la.

Em paralelo, lanca **Animations on the Web** em animations.dev. Plataforma propria construida do zero — code editor embutido no curso (nao precisa clonar repo), salvamento automatico, exercicios interativos, lifetime access. O curso comeca focado em Framer Motion mas Emil ja anuncia modulo de CSS pura para alcancar audiencia maior.

## Estilo de Trabalho

- **Code-first.** Emil nao desenha mockup primeiro. Ele prototipa em codigo. Anima em codigo. Decide em codigo.
- **Source code reading.** Emil le o source de Framer Motion, Radix UI, React Aria. Conhece como as coisas funcionam por dentro.
- **Detalhe obsessivo.** Vaul tem um snap point intermediario que "encaixa" so se voce arrasta com velocidade x acima de y. Esse detalhe esta em alguma issue do GitHub. Ninguem teria notado se Emil nao tivesse implementado.
- **Open source como portfolio vivo.** Sonner e Vaul nao sao lib + readme. Sao demonstracao publica do que ele defende.
- **Curso como pedagogia.** animations.dev nao e "aprenda Framer Motion em 30 dias". E "aprenda a pensar como Emil pensa quando olha uma animacao".
