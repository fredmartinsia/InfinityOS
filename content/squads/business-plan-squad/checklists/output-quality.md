# Checklist — Output Quality do business-plan-squad

> Gate de qualidade obrigatório antes de entregar o Business Plan final ao usuário.

## A) Substância (não placeholder)

- [ ] Zero ocorrências de "TODO", "[a preencher]", "PLACEHOLDER", "X" como valor
- [ ] Todos os números têm fonte (própria pesquisa primária, dataset público, ou marcação "estimativa baseada em [premissa]")
- [ ] Todas as citações têm autor e (se possível) ano/fonte
- [ ] Nenhuma seção fica vazia ou só com bullet "ver mais"

## B) Onboarding e checkpoint

- [ ] 8 perguntas de onboarding respondidas (mesmo que com "ainda não sei — PENDENTE")
- [ ] Checkpoint de fundo perdido em Portugal explicitamente respondido (SIM/NÃO)
- [ ] Se SIM: handoff para `/capital-chief` documentado, sessão encerrada
- [ ] Se NÃO: workflow completo dos 7 especialistas seguido

## C) Validação (Blank + Ries)

- [ ] Hipóteses críticas listadas (pelo menos 5)
- [ ] Plano de Customer Discovery definido OU dados de validação real apresentados
- [ ] MVP definido com tipo + métricas + critério objetivo de pivot/perseverar
- [ ] Se ainda não houve discovery, BP marca "validação pendente" como risco principal

## D) Modelo (Osterwalder)

- [ ] Business Model Canvas com TODOS os 9 blocos preenchidos
- [ ] Value Proposition Canvas com Customer Profile (Jobs/Pains/Gains) E Value Map (Products/Pain Relievers/Gain Creators) preenchidos
- [ ] Sem bloco "trivial" — cada bloco tem substância
- [ ] Customer Segments é específico (não "todo mundo")

## E) Mercado (Aulet + Porter)

- [ ] TAM tem método **bottom-up** + **top-down** (não só top-down)
- [ ] Beachhead market identificado e justificado
- [ ] End User Profile detalhado (não persona genérica)
- [ ] DMU (Decision Making Unit) mapeada
- [ ] 5 Forças aplicadas ao setor específico (não genéricas)
- [ ] Atratividade do setor classificada (alta/média/baixa) com justificativa
- [ ] 5-10 concorrentes listados com modelo + posicionamento + fraquezas
- [ ] Cadeia de Valor mapeada
- [ ] Estratégia genérica escolhida = UMA (sem "stuck in the middle")

## F) Defensibilidade (Thiel)

- [ ] 7 Perguntas de Zero to One respondidas
- [ ] "Secret" do negócio identificado (não óbvio)
- [ ] Pelo menos 1 das 4 características de monopólio mapeada (Proprietary Tech / Network Effects / Economies of Scale / Branding)
- [ ] Plano para construir defensibilidade nos primeiros 24 meses

## G) Financeiro (Damodaran)

- [ ] CAPEX detalhado por categoria (tangível + intangível + working + pré-operacional)
- [ ] CAPEX separa único de manutenção
- [ ] OPEX mensal com rampa realista (não constante desde mês 1)
- [ ] DRE 5 anos com premissas explícitas (não "porque sim")
- [ ] Cash Flow 5 anos
- [ ] WACC calculado usando dataset Damodaran do país específico
- [ ] DCF com Terminal Value (g ≤ GDP nominal — nunca 5%+)
- [ ] 3 cenários (Pessimista/Base/Otimista) com premissas que mudam explicitadas
- [ ] Sensibilidade para 2-3 variáveis críticas
- [ ] Payback estimado (simples + descontado)
- [ ] Valuation indicativa apresentada com ranges (não número único pretensioso)

## H) Estrutura do BP final (10 seções)

- [ ] 1. Executive Summary (2 páginas, síntese real do plano)
- [ ] 2. Empresa / Promotor
- [ ] 3. Análise de Mercado
- [ ] 4. Modelo de Negócio
- [ ] 5. Estratégia Competitiva
- [ ] 6. Plano Operacional
- [ ] 7. Time + Plano de Pessoas
- [ ] 8. Plano Financeiro
- [ ] 9. Análise de Risco + Mitigações
- [ ] 10. Apêndices

## I) Idioma e formatação

- [ ] Idioma único (pt-BR ou pt-PT) — sem mistura
- [ ] Formatação Markdown consistente
- [ ] Tabelas legíveis
- [ ] Sem emojis no BP final (estes ficam só nos cumprimentos dos agentes)

## J) Riscos + Mitigações

- [ ] Pelo menos 5 riscos listados (mercado, operacional, financeiro, regulatório, de execução)
- [ ] Cada risco tem mitigação proposta
- [ ] Risco específico do país de operação considerado

## K) Anti-claims

- [ ] BP NÃO promete sucesso garantido
- [ ] BP NÃO promete captação garantida
- [ ] BP NÃO usa linguagem de marketing exagerada ("revolucionário", "único no mundo" sem prova)
- [ ] BP é honesto sobre as incertezas (marca como riscos, não esconde)

## L) Acionabilidade

- [ ] Próximos 30 / 60 / 90 dias listados como ações concretas
- [ ] Lista de próximos 10 clientes-alvo (nominal ou perfis específicos)
- [ ] Cronograma de execução com marcos

---

**Se algum item desta lista falhou:** voltar ao especialista responsável antes de entregar o BP final.

**Última checagem antes da entrega:** o `/business-plan-chief` revisa o BP completo procurando inconsistências entre as seções (por exemplo: TAM diz X, mas projeções financeiras assumem Y inconsistente com X).
